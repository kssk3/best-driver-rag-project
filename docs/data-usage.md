# 데이터 이용과 보안 점검

색인에 쓰는 자료의 이용 조건, 외부 모델 전송, 비밀정보·캐시·로그 관리를 점검한 기록이다. 문서 목록은 [문서 목록](documents.md)에 있다. 점검일 2026-11-26. 법률 자문이 아니라 팀의 내부 점검이다.

## 1. 자료의 이용 조건

| 항목 | 내용 | 근거 |
| --- | --- | --- |
| 자료 | 서울특별시 서대문구·송파구의 폐기물 관리 조례, 시행규칙과 별표·별지(23건) | [문서 목록](documents.md) |
| 출처 | 국가법령정보센터(법제처) 자치법규. 승인된 Open API로 본문·첨부 XML을 수집했다 | `raw/manifest.json`의 `api_access_review` |
| 저작권 | 조례와 규칙은 저작권법 제7조제1호가 정한 보호받지 못하는 저작물에 해당한다 | 번들 `raw/manifest.json`의 본문 4건 검토 기록(이정은, 2026-11-24) |
| API 이용 조건 | 출처 표시, 원문 위조·변조 금지, 제3자 권리 준수, 과도한 호출 금지, 이용조건 변경 확인 | `api_access_review.conditions` |
| 재검토 기한 | 2027-01-01(팀이 지정한 내부 기한이며 API 키의 정확한 만료일은 확인하지 못했다) | `api_access_review.expires_at` |
| 개인정보 | 자료에 없다. 서식(별지)은 빈 양식이며 색인하지 않는다 | [문서 목록](documents.md) |

수집 번들의 `usage_status`는 `index_and_model_use_unreviewed`(색인·외부 모델 이용은 별도 검토)였고, 이 별도 검토를 아래 2장에서 결정한다.

## 2. 색인과 외부 모델 이용 결정 (2026-11-26)

팀이 합의했다(승주님 전달). 위 이용 조건을 지키는 범위에서 다음을 허용한다.

- **색인**: 조례·시행규칙·별표 본문을 청크로 나눠 로컬 색인에 저장한다. 출처 표시를 위해 청크마다 문서 ID, 제목, 원문 위치, URL을 남기고 본문을 고치지 않는다.
- **외부 모델 전송**: 질문과 검색된 청크 본문을 OpenAI(임베딩 `text-embedding-3-small`, 답변·재정렬·판정 `gpt-6-luna`)에 보낸다. 자료는 공개 자치법규라 전송해도 비공개 정보가 없다. 사용자 질문 본문도 모델 제공자에게 전달되므로 질문에 개인정보를 넣지 않도록 안내해야 한다(화면에 이 안내가 있는지는 확인하지 않았다).
- **외부 문서**: 서대문구청 생활쓰레기 배출 안내 페이지는 공공누리 제1유형 표시를 확인해 [별도 수집](official-guide-collection.md)했고 이 색인에는 넣지 않았다.

이 결정은 위 조건이 바뀌면 다시 검토한다.

## 3. 비밀정보와 키

- API 키(`OPENAI_API_KEY`, `LANGFUSE_*`)는 로컬 `.env`에만 두고 저장소에 올리지 않는다. `.env`와 `data/processed/`는 `.gitignore`에 있고 [.env.example](../.env.example)은 값 없는 예시다.
- PR마다 Gitleaks 검사가 돈다. `dev` 푸시만으로는 돌지 않는다([CI 설명](CI-AND-DEPENDENCIES.md)). 평가 결과를 저장소에 올리기 전에 키 형식(`sk-`)과 개인 경로·이메일이 없는지 확인했다(`results/dev10-abc-2026-11-26/`, `results/final-*/`).
- Open API 응답은 인증값(OC)을 제거한 공유본만 번들에 있다(`sharing_metadata`, `review/search_response_redactions.json`).

## 4. 로그와 추적

- 실행 기록은 질문, 검색 후보, 답변, 시간을 담는다. 로컬 `results/local/`은 Git에서 제외된다. 공유하는 평가 결과는 질문이 평가셋의 가상 질문뿐이다.
- Langfuse 추적은 기본이 꺼져 있다. `RAG_LANGFUSE_TRACE=1`을 켜면 모델 입력(프롬프트·근거 본문)이 팀 서버로 전송된다. 사용자 질문에 개인정보가 있을 수 있는 실제 서비스에서는 켜지 않는다([설정](TEAM-SETUP.md#팀-langfuse-설정)).
- 화면의 검증·비교 대시보드는 내부 데모용이다. 외부 공개 전에는 환경변수로 끄도록 바꿔야 한다(후속).

## 5. 캐시

이 프로젝트는 캐싱 대신 질문 다듬기(쿼리 리라이트)를 선택했고 응답 캐시를 구현하지 않았다. 사용자별 캐시 범위 문제가 없다. 화면과 평가에서 쓰는 질문 다듬기(`make_catalog_rewriter`)는 품목 사전 기반이며 코드에 모델 호출이 없고, 입력은 해석된 질문뿐이라 정답·허용 근거를 받지 않는다.

## 6. 남는 위험과 한계

- 공개 배포나 실사용 보안 수준을 주장하지 않는다. 작은 평가셋과 제한된 문서 범위의 검증이다.
- 외부 모델 제공자의 데이터 취급 정책은 이 문서에서 확인하지 않았다. 실서비스 전에 제공자 약관을 검토해야 한다.
- 조례·규칙은 개정될 수 있다. 시행일(`effective_date`)이 바뀌면 색인을 다시 만들고 평가셋의 근거 매핑을 갱신한다.
