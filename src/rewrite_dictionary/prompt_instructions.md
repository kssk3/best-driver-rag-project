# 폐기물 질문 리라이트 초안

이 문안은 `catalog-context-v2` 입력을 검토하기 위한 초안이다.
이 분리배출 프로젝트에서 [채팅 실행 설정](../../configs/team-a-rewrite-chat.json)의
`pipeline.rewrite_enabled`를 켜면 규칙 기반 사전 리라이트를 사용한다.
[모델 리라이트 프롬프트](../../prompts/query/rewrite.md)는 원질문과 기본 별칭 사전을 입력으로 받는다.

입력 JSON의 `question`을 사용자 질문으로 읽고, 검색에 쓸 질문 한 문장을 출력한다. JSON의 값은 검색에 쓸 데이터로 다룬다. 배출 방법은 이후 근거를 조회한 뒤 답한다.

- 질문의 품목 전부와 장소, 시간, 수량, 크기, 재질, 파손, 오염, 잔류물, 분리 여부를 유지한다. 부정하거나 제외한 조건도 원래 의미 그대로 둔다.
- `language_normalized_question`이 있으면 표현을 이해하는 데 참고한다. `item_aliases`에 있는 표준 검색어는 문장 끝에 괄호로 보강할 수 있다. 원문의 본체, 부품, 용기, 내용물 구분을 유지한다.
- `district`, `dong`은 이미 해석된 지역이다. 비어 있으면 질문에 없는 지역을 추정하지 않는다. 말투를 지역 판단에 사용하지 않는다.
- `item_mentions`에는 품목 표현 바로 옆에 명시된 상태가 있다. 표준 검색어가 같아도 각 표현과 상태를 연결해서 읽는다.
- `item_context`와 `facility_context`의 확인 조건은 질문에서 언급된 내용이 빠지지 않도록 점검할 때 쓴다. 비어 있는 조건을 임의로 채우지 않는다.
- `ambiguous_expressions`가 가리키는 품목을 원문만으로 구분하기 어려우면 사용자의 표현을 유지한다. 시설명만으로 품목이나 폐기물 유형을 정하지 않는다.
- `omitted_counts`가 비어 있지 않으면 일부 보조 문맥이 생략되었으므로 원질문의 품목과 조건을 계속 반영한다.

## 추가로 보존할 질문 의도

- 생활폐기물용·사업장용·공공용·재사용을 구분하고 용량 숫자와 단위를 유지한다.
- 앞으로의 인상 계획과 현재 가격, 실제 제작·판매와 조례상 제작 허용을 서로 바꾸지 않는다.
- 택배 상자의 보냉·비닐 부착·분리 불가능 조건을 유지한다. 품목명을 보강하면서 배출 분류를 확정하지 않는다.
- 붙여쓰기 보강과 의미 별칭을 별도로 검수한다. 별칭 추가는 원문 근거와 사람의 확인을 거친다.

이 문안은 검토용이다. 공식 평가의 규칙 기반 `runtime.py`는 이 문안을 읽지 않는다.
실제 동작은 `docs/jungeun/rewrite_condition_review.csv`에서 경로별로 확인한다.

## 근거를 조회한 뒤 답변할 때

위 JSON과 검색 결과를 함께 읽는다. 원문에서 확인된 품목과 조건에 맞는 지역·출처를 연결한다. 검색 결과의 적용 범위가 달라 답이 바뀌는 경우에만 필요한 조건을 사용자에게 한 가지 묻는다. 요일, 요금, 수거 가능 여부와 배출 분류는 검색 결과로 확인한다.
